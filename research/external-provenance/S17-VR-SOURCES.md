# S17 — External Provenance: VR Presence and 6DoF

**Research date:** 2026-10-25. Official runtime standards, vendor technical guidance and original peer-reviewed perception research selectively inspected. No complete code audit, no on-device test, and no guarantee of comfort. Source inspiration is not a claim of proprietary source access; MGR-native design is maintained separately in `research/chapters/S17-VR-PRESENCE.md`.

## No hardware, no proof

The references support **how** to implement and test XR. They do not show the user's computer currently has an XR headset/runtime, that Forge is presenting correct independent per-eye buffers, that the system measures total motion-to-photon latency, or that users find MGR worlds safe and comfortable. The Blender desktop test cannot verify headset lenses, hand sensors, display persistence, head tracking or real-world boundaries.

## Reproducible MGR experiments

1. Build a deterministic per-eye calibrated stereo room with known metric object positions and compare both projected views to analytic disparity.
2. Emulate tracking pose changes, loss of tracking, fallback to controllers, re-centering and changing origin; reject invalid reference-space transforms.
3. Enumerate actual OpenXR extension and device capability only when runtime/hardware available; never silently advertise 6DoF/hand joints.
4. On a real headset, collect CPU/GPU app time, missed frames, refresh rate, tracking latency estimates, runtime reports, temperature if exposed and sustained frame health. Measure true motion-to-photon separately with suitable external measurement.
5. With informed participant consent, evaluate headset comfort, near/far readability, collision boundary, snap vs smooth turning and safe emergency exit across realistic users and conditions.

**Source handling:** Cite the specifications and papers, review SDK licenses individually before vendoring, avoid copying third-party characters/scenes, and treat raw head/hand/gaze traces as privacy-sensitive.
